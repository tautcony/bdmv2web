# HDMV navigation support matrix

This matrix records what the current implementation decodes and executes against pinned VideoLAN libbluray 1.5.0, commit `d75c88e54c893e5cbf4c61d356477655eb435769` (LGPL-2.1), at the source files listed below. The State / fixture column lists the tests that cover each row; those tests assert this implementation against that reference. `faults` marks rows where the decoder recognizes the field combination and the VM records a diagnostic and enters `faulted`.

The rows below describe the current implementation. The audit record in [`docs/archive/reviews/review-2026-11-06-hdmv-vm-conformance/index.md`](../archive/reviews/review-2026-11-06-hdmv-vm-conformance/index.md) holds the pre-fix evidence and the per-item record.

## Evidence and encoding

The parser-facing input is M1 `MovieInstruction`: three big endian uint32 `words`, 24 hex characters in `bytes`, and `SourceLocation { path, origin, offset }`. The decoder validates that the words reproduce the raw bytes. Button command streams use the same `RawCommand` interface and decoder.

## Sources

`SourceLocation.path` is relative to the BDMV root and omits the `BDMV/` prefix. A MovieObject instruction can use `MovieObject.bdmv`; `origin` records `primary` or `backup`, and `offset` is the decimal byte offset within that file.

The field layout below is the layout implemented by the pinned `libbluray` MOBJ reader. It is implementation evidence only:

| Word 0 bits | Field | Notes |
| --- | --- | --- |
| 31–29 | operand count | libbluray reads 3 bits |
| 28–27 | group | 0 branch, 1 compare, 2 set; 3 unknown |
| 26–24 | subgroup | branch: GOTO/JUMP/PLAY; set: SET/SETSYSTEM |
| 23, 22 | immediate operand 1, 2 | Reserved or ignored when an operand is not present |
| 21–20 | reserved | Nonzero is reported as `HDMV_RESERVED_BITS_NONZERO`; execution continues |
| 19–16 | branch option | Branch subgroup option |
| 15–12 | reserved | Nonzero is reported as `HDMV_RESERVED_BITS_NONZERO`; execution continues |
| 11–8 | compare option | Compare operation |
| 7–5 | reserved | Nonzero is reported as `HDMV_RESERVED_BITS_NONZERO`; execution continues |
| 4–0 | set option | Arithmetic or SETSYSTEM operation |
| Word 1, Word 2 | operands | Raw uint32 values; register references are checked before access |

`SET_STREAM` follows the pinned libbluray 1.5.0 behavior: for non-immediate operands it preserves `0xf000f000`, reads the two GPRs selected by the low and high 12-bit fields, and combines their low 12-bit values. It conditionally selects PSR1 primary audio, PSR0 IG, PSR3 angle, and PSR2 PG/TextST stream; PSR2 display bit31 follows destination bit14. The action carries raw/resolved words and nullable selections. `SET_SEC_STREAM` uses the same GPR selector encoding and applies the secondary audio/video and PiP PG/TextST fields to PSR14/2. `SET_BUTTON_PAGE` preserves its operand flags, dereferences the GPR named by bits 11–0, and uses the low 30 bits of that GPR value. MovieObject commands conditionally update PSR10 (low 16 destination bits) and PSR11 (low 8 source bits). IG-button commands emit the packed request and report termination of that button command sequence without stopping the shared VM; there is no VM wait for that immediate action. Page switching and button selection remain outside this VM instruction change.

## VM, bridge, trace, and analysis boundary

The VM has `idle`, `running`, `suspended`, `stopped`, and `faulted` states. Actions allocate a generation before publication. A continuation accepts only a matching `generation` and `responseTo`; unrelated, stale, and duplicate events are traced and ignored. A playlist completion wait no longer blocks navigation: `TOP_MENU`, `POPUP_MENU`, `RETURN`, and IG button programs run while the MovieObject stays suspended at its playlist action. Only a pending title transition (`JUMP_TITLE`/`CALL_TITLE`) rejects navigation input until `selectTitle()` resolves it. Media errors and unavailable events end the matching wait as `stopped` with a diagnostic. `TOP_MENU` checks the MovieObject `menuCallMask`, parks the playing continuation when `resumeIntention` is set, and emits `TITLE_SEARCH title=0`. `POPUP_MENU` emits `MENU_CALL` without a VM wait; the runtime gates it with the page/playlist UO mask. Playback status events update PSR6, PSR5=0xffff, PSR7 from `PLAYITEM_CHANGED`, and PSR8 from `TIME_UPDATED`/`MEDIA_SEEKED` (`presentationTime` in 45 kHz; `mediaTimeSeconds` is converted). Pending action queue size and instructions per turn have enforced bounds. VM limits come from core `DEFAULT_LIMITS` and can be overridden through `VmOptions.limits` or CLI `build --limits FILE`. `maxCallDepth` is a CALL enable switch, described in the [limits table](../guides/development.md#contracts).

Wait conditions are explicit application policy. Playlist commands use `ended`; `MEDIA_STARTED` updates playback status without consuming the wait. A `seeked` wait consumes `MEDIA_SEEKED`; `TIME_UPDATED` and `MEDIA_SEEKED` also update PSR8 without resuming a playlist wait. `still-completed` has no current producer. Keyboard and pointer input enter through the shared runtime `MenuController`, which applies the current IGS page UO mask to each operation before dispatching it. The VM's normalized `MENU_INPUT` API applies the same `uoAllowed` decision regardless of whether `channel` is `keyboard` or `pointer`. Correlated `MEDIA_*` and still-completion events use the system-event path and are not filtered by the user-operation mask; a user event during a playlist wait leaves the media continuation intact. Focused VM and runtime tests cover allowed and blocked keyboard/pointer operations and media completion when a user-operation payload says input is denied. The field mapping follows the pinned libbluray UO handling and IGS page mask representation. Static graph analysis classifies dynamic targets, unresolved resume/play edges, unknown commands, and budget exhaustion as unresolved.

No DOM, media element, renderer, decoder, BD-J execution, or disk access is part of this package. Source-derived checkpoints for Compare, Call/Resume, and playlist completion are in `packages/hdmv/src/fixtures/libbluray-1.5.0-source-derived-reference-golden.json`; the Vitest suite reports the first differing checkpoint. Expected states are derived from the pinned libbluray source.
