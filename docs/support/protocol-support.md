# Protocol support boundary (M1)

核验日期：2026-11-10。此表记录 M1 实现的结构解析范围和证据状态。主要行为依据为固定 revision 的开源实现；对适用范围外、版本差异和实现冲突必须单独记录。BDA 历史公开白皮书只作其明确覆盖范围内的格式/架构背景，不是规范正文，也不替代实现证据或测试。

## Evidence tiers

- `implementation-reference`: behavior is traced to a pinned implementation revision, exact file/location, and applicable license. For BDMV/HDMV the primary reference is VideoLAN libbluray 1.5.0, commit `d75c88e54c893e5cbf4c61d356477655eb435769`, LGPL-2.1. It establishes what that implementation does within its tested scope.
- `cross-reference`: another pinned implementation or a public whitepaper is used only where its source and scope are explicit. Whitepaper references include title/version and printed page(s); they provide background, not normative requirements.
- `project-test`: synthetic fixtures and assertions prove the behavior of this code only. Independent golden data records its source, version/case, derivation or comparison method, and limits. Same-lineage forks or ports are not independent by default.
- `unverified`: implementation/tests exist but cross-checks or path coverage are incomplete, or independent expected values are missing.
- `unsupported`: the product does not implement the named execution or playback behavior.

## Status rules

- `unverified`: implementation and/or project tests exist, but stated evidence scope, cross-checks, or independent expected values remain incomplete.
- `unsupported`: the product does not implement the named execution or playback behavior.
- `supported`: not assigned in M1. No format or version is currently declared supported.

Fixtures in `packages/test-fixtures` are project-authored binary byte builders and hand-authored expectations. They test parser behavior and boundaries, not independent protocol correctness. For each behavior record evidence tier, exact source revision/file/license, applicable whitepaper title/version/page, test/golden provenance, and conflict or unsupported scope. The pinned implementation is the primary behavior reference; project tests and independent goldens record the validation actually completed.

The parser's version gate accepts only the candidate tags shown above; `0240` is the 3D/MVC profile. Unknown primary versions are rejected before a format is returned. `packages/bdmv-parser/src/parser.test.ts` checks this for INDX, MOBJ, MPLS, CLPI, sound and referenced BDJO records. Candidate version field layouts remain `unverified`; implementation fixtures do not establish version-wide protocol conformance.

## Sources

`SourceLocation.path` is relative to the BDMV root and omits the `BDMV/` prefix. For example, a playlist source uses `PLAYLIST/00001.mpls`; a root metadata source uses `index.bdmv`. `origin` records `primary` or `backup`, and `offset` is the decimal byte offset within that file.

## Evidence and fixture gaps

- BDA specification books are agreement-gated; the public whitepapers listed in `.reference-cache/specs/SOURCE.md` cover architecture and format background.
- The primary implementation reference is libbluray 1.5.0 under LGPL-2.1. libhdmv is Alpha and its field layout conflicts with libbluray, so it is a cross-check of source lineage only.
- The repository contains project-authored bytes and no commercial media. Their expected values come from the parser branches they were written for.
- Every candidate format version remains `unverified`; parsed field coverage is reported separately from protocol evidence.
- Case-variant BDMV ambiguity is tested only when the filesystem allows both names; the current case-insensitive workspace filesystem cannot exercise that branch.
- CLPI ClipMark and selected MPLS/CLPI ExtensionData payloads are parsed into source-linked fields. Unknown ExtensionData entries retain ID, version, bounds, and an unparsed diagnostic. MPLS angle declarations and STN categories are retained; playback selection is unsupported. MovieObject command target resolution, BD-J execution, transport streams, and media payload decoding are outside the M1 parser output.
- META/DL XML parsing accepts local manifests, built-in XML entities, numeric character entities, comments, processing instructions and CDATA. DTD and entity declarations are rejected; external resources are not loaded.
- `ParsedDisc.discInfo.uhd` reports the INDEX extension 3.1 signalling only: what the disc declares, not a playback-capability decision.
- Unknown versions are rejected and backup fallback does not hide them. This version gate is an implementation rule for the listed candidate tags.
