# Protocol support boundary (M1)

核验日期：2026-11-10。此表记录 M1 的结构解析字段、独立样本对照和剩余的字段级缺口。主要行为参考为固定 revision 的开源实现。BDA 历史公开白皮书仅覆盖其明确列出的格式与架构背景。

## Evidence tiers

- `implementation-reference`: behavior is traced to a pinned implementation revision, exact file/location, and applicable license. The primary BDMV/HDMV reference is VideoLAN libbluray 1.5.0, commit `d75c88e54c893e5cbf4c61d356477655eb435769`, LGPL-2.1.
- `cross-reference`: another pinned implementation or a public whitepaper is used with its source and scope recorded. Whitepapers provide architecture and format background.
- `project-test`: project-authored fixtures and assertions check parser behavior and bounds. They do not supply independent expected values.
- `sample-checked`: the named fields in the named sample were compared with an independent tool or source output. The record names the file, format version, fields, and comparison method.
- `unverified`: listed fields or variants have no independent expected-value comparison in the available sample set.
- `unsupported`: the product does not implement the named execution or playback behavior.

## Status rules

- `sample-checked` applies to the fields and samples named in the table.
- `unverified` applies to the explicitly listed versions, fields, and variants without an independent comparison.
- `unsupported` applies to the named execution or playback behavior.
- `supported` is not assigned in M1.

Fixtures in `packages/test-fixtures` use project-authored binary builders and expectations. The test corpus includes real BDMV samples under `test-data/fixtures/hdmv-navigation/disc-data`; the Spider-Man sample was supplied locally and remains outside tracked files. Independent comparison details are recorded in `openspec/changes/expand-readonly-disc-inspection/verification.md`.

The parser accepts version tags `0100`, `0200`, `0240`, and `0300`; `0240` is the 3D/MVC profile. Unknown primary versions are rejected before a format is returned. Real sample files in the current fixture corpus use `0200` and `0300`; `0100` samples are project-authored, and no `0240` sample is present. Each `sample-checked` status names its compared fields and source files.

## Sources

`SourceLocation.path` is relative to the BDMV root and omits the `BDMV/` prefix. For example, a playlist source uses `PLAYLIST/00001.mpls`; a root metadata source uses `index.bdmv`. `origin` records `primary` or `backup`, and `offset` is the decimal byte offset within that file.

## Evidence and fixture gaps

- BDA specification books are agreement-gated; public whitepapers in `.reference-cache/specs/SOURCE.md` cover architecture and format background.
- The primary implementation reference is libbluray 1.5.0 under LGPL-2.1. libhdmv is Alpha and its field layout conflicts with libbluray; its source is recorded as a cross-reference.
- Real sample comparisons cover selected 0200/0300 fields. Candidate versions `0100` and `0240`, fields and variants listed in the table remain `unverified`.
- Case-variant BDMV ambiguity is tested only when the filesystem allows both names; the current case-insensitive workspace filesystem cannot exercise that branch.
- CLPI ClipMark and selected MPLS/CLPI ExtensionData payloads have parser coverage. Unknown ExtensionData entries retain ID, version, bounds and an unparsed diagnostic. MPLS angle declarations and STN categories are retained; playback selection is unsupported.
- META/DL XML parsing accepts local manifests, built-in XML entities, numeric character entities, comments, processing instructions and CDATA. DTD and entity declarations are rejected; external resources are not loaded.
- `ParsedDisc.discInfo.uhd` reports INDEX extension 3.1 signalling read from the disc.
- Unknown versions are rejected, and backup fallback does not hide them. This version gate accepts the candidate tags listed above.
