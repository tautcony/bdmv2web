## 与已决策项的关系

- **D6（本地桥 GET + token 在 URL）**：已决策"先不修改"，但它不是遗留问题，而是**有意的残余风险**。它在 `converge` 的 §I 与 README 已知限制中各有一条，不进本表。
- **D9（完整性校验未实现）**：同上，已通过"减承诺"显式化为 `not-verified` 语义，不进本表。
- **X4 与 D9 的区别**：D9 处理的是"声称的能力不存在"（承诺 → 未验证）；X4 是"已有的失败被分类错"（fail → not-verified）。前者是诚实性问题，后者是正确性问题，不要合并处理。

## 建议的后续顺序

若要把它们变成 change，按"影响 × 可验证性"排序：

1. **X1**（可能拒绝合法输入）——需要样本，但影响最直接。
2. **X2**（单文件损坏拖垮整条命令）——与 CLI 的"部分成功"语义相关，可并入未来的错误恢复 change。
3. **X4**（状态分类错误）——改动小，但会让既有报告数字变化，需同步基线。
4. **X3**（防御性加固）——无实际触发证据前不动。
5. **X5**（配置静默失效）——D3 完成后顺手做，成本最低。
