# Spec Delta

## Purpose

让交付包在“只发布产物”的布局下仍可构建，并让性能优先级由可复现的基准数据决定，而不是代码阅读的印象。

## ADDED Requirements

### Requirement: 发布布局下的构建可复现

系统 SHALL 使构建只依赖已声明的产物与依赖关系，不依赖同一 monorepo 内的源码文件路径；发布包的内容范围必须显式限定。

#### Scenario: 源码不在包内

- **WHEN** 下游仅安装发布产物（无 `src/` 目录）后执行菜单打包
- **THEN** 打包成功，不因缺少源码文件失败

#### Scenario: 构建期读取源码

- **WHEN** 打包过程尝试读取任一依赖包的 `src/**/*.ts`
- **THEN** 该行为被视为契约违反，测试失败并指出路径

#### Scenario: 发布内容范围

- **WHEN** 对可发布的包执行打包清单检查
- **THEN** 清单只含构建产物与显式声明的资源，不含 `src/` 与测试文件

### Requirement: 性能基准与预算

系统 SHALL 为已知的大输入热点提供可复现基准，记录样本、环境与结果；优化必须由数据支撑，并保留未优化项的原因。

#### Scenario: 基准可复现

- **WHEN** 在同一环境重复执行基准
- **THEN** 同一 case 的结果波动在记录范围内，样本生成方式与命令可被他人复现

#### Scenario: 优化前有数据

- **WHEN** 提交一项性能改动
- **THEN** 该改动对应基准的前后数据同时存在；无数据支撑的重构不得以性能名义提交

#### Scenario: 复杂度改善的判定

- **WHEN** 某个 case 在输入规模翻倍时耗时接近 4 倍增长
- **THEN** 该 case 判为超线性并优先处理；修复后规模翻倍的耗时增长应显著低于 4 倍

#### Scenario: 未优化项留档

- **WHEN** 某项热点经实测判定为可接受或暂不处理
- **THEN** 记录触发条件与不处理原因，不静默跳过

#### Scenario: 回归告警

- **WHEN** 同一 case 相对记录基线退化超过约定阈值
- **THEN** 需要给出原因说明，不能当作无变化
